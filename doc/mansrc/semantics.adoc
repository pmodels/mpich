= MPI Function Semantics
When we generate man pages, the description section will be looked up from this file.
Use the following format to specify semantics or notes for an MPI Function

// tag:: MPI_Func_name[]
Describe semantics for MPI_Func_name.
// end:: MPI_Func_name[]

//tag::MPI_Abort[]
*MPI_Abort* makes a best attempt to abort all MPI processes in the group of `comm`.
This operation is nonlocal and may abort all connected processes if the implementation cannot abort only the processes represented by `comm`. When using the World Process Model with no spawned, accepted, or connected processes, this has the effect of aborting all processes associated with MPI_COMM_WORLD. In the Session Process Model, if an MPI process has instantiated multiple sessions, invoking *MPI_Abort* on a communicator derived from one session results in all MPI processes in the union of the process sets of these sessions being aborted. The `errorcode` may be returned from the executable or from the MPI process startup mechanism (e.g., mpiexec), which is an aspect of quality of the MPI library but not mandatory.
//end::MPI_Abort[]

//tag::MPI_Init[]
*MPI_Init* initializes the MPI execution environment using the World Process Model.
A call to *MPI_Init* has the same effect as a call to *MPI_Init_thread* with `required` = MPI_THREAD_SINGLE. Subsequent calls to *MPI_Init* or *MPI_Init_thread* are erroneous. Threads may be spawned before MPI is initialized, but MPI_COMM_WORLD and MPI_COMM_SELF are not valid for use as communicators until *MPI_Init* or *MPI_Init_thread* is invoked. Portable third party libraries may be written to accommodate any provided level of thread support, and *MPI_Query_thread* may be used to check the level of thread support with which the user initialized MPI.
//end::MPI_Init[]

//tag::MPI_Init_thread[]
*MPI_Init_thread* initializes the MPI execution environment and thread environment using the World Process Model.
The `required` parameter specifies the desired level of thread support from `MPI_THREAD_SINGLE`, `MPI_THREAD_FUNNELED`, `MPI_THREAD_SERIALIZED`, or `MPI_THREAD_MULTIPLE`, and `provided` returns the actual level supported by the implementation. Subsequent calls to *MPI_Init* or *MPI_Init_thread* are erroneous. Threads may be spawned before MPI is initialized, but MPI_COMM_WORLD and MPI_COMM_SELF are not valid for use as communicators until *MPI_Init* or *MPI_Init_thread* is invoked. Portable third party libraries may be written to accommodate any provided level of thread support, and *MPI_Query_thread* may be used to check the level of thread support with which the user initialized MPI.
//end::MPI_Init_thread[]

//tag::MPI_Psend_init[]
*MPI_Psend_init* creates a partitioned communication send request for point-to-point communication between two processes.
This operation is local and may return before the communication completes. It is erroneous to provide a `partitions` value less than or equal to zero. Partitioned communication allows multiple actors, such as threads or tasks, to independently contribute data to a single communication operation; using a small number of receiver-side partitions may provide higher performance.
//end::MPI_Psend_init[]

//tag::MPI_Precv_init[]
*MPI_Precv_init* creates a partitioned communication receive request for point-to-point communication between two processes.
This operation is local and may return before the communication completes. It is erroneous to provide a `partitions` value less than or equal to zero, and wildcards for `source` and `tag` are not allowed. Partitioned communication allows multiple actors, such as threads or tasks, to independently contribute data to a single communication operation.
//end::MPI_Precv_init[]

//tag::MPI_Pready[]
*MPI_Pready* is a send-side call that indicates a given partition is ready to be transferred.
Partitioned communication allows multiple actors, such as threads or tasks, to independently mark partitions as ready. It is erroneous to use *MPI_Pready* on any request that does not correspond to a partitioned send operation. It is erroneous to specify a `partition` number that is equal to or larger than the number of partitions, or to call *MPI_Pready* on an active partition.
//end::MPI_Pready[]

//tag::MPI_Pready_range[]
*MPI_Pready_range* is a send-side call that marks a contiguous range of partitions as ready to be transferred.
A call to *MPI_Pready_range* has the same effect as calling *MPI_Pready* for each partition from `partition_low` to `partition_high` in some arbitrary order. It is erroneous to specify a partition number that is equal to or larger than the number of partitions, or to call *MPI_Pready_range* on an active partition.
//end::MPI_Pready_range[]

//tag::MPI_Pready_list[]
*MPI_Pready_list* is a send-side call that marks an array of partitions as ready to be transferred.
A call to *MPI_Pready_list* has the same effect as calling *MPI_Pready* for each partition specified in `array_of_partitions` in some arbitrary order. It is erroneous to use *MPI_Pready_list* on any request that does not correspond to a partitioned send operation. It is erroneous to specify a partition number that is equal to or larger than the number of partitions, or to call *MPI_Pready_list* on an active partition.
//end::MPI_Pready_list[]

//tag::MPI_Parrived[]
*MPI_Parrived* tests partial completion of partitioned receive operations.
This is a local operation that returns `flag` = true if the specified `partition` is complete; the request is not marked as complete by this procedure. If `request` is null or inactive, the operation returns `flag` = true. It is erroneous to call *MPI_Parrived* on a request that does not correspond to a partitioned receive operation.
//end::MPI_Parrived[]

//tag::MPI_Comm_revoke[]
*MPI_Comm_revoke* notifies all MPI processes in the groups associated with a communicator that the communicator is revoked.
This operation is nonlocal and completes non-local MPI operations on `comm` at all MPI processes by raising an error of class MPI_ERR_REVOKED. This procedure is not collective and does not have a matching call on remote MPI processes. All non-failed MPI processes belonging to `comm` will be notified of the revocation despite failures. In a multithreaded application, a thread calling *MPI_Comm_is_revoked* may return true before the operation that raises the first exception of class MPI_ERR_REVOKED has completed in a concurrent thread.
//end::MPI_Comm_revoke[]

//tag::MPI_Comm_is_revoked[]
*MPI_Comm_is_revoked* queries whether a communicator is revoked at the calling process.
In a multithreaded application, a thread calling *MPI_Comm_is_revoked* may return `flag` = true before the operation that raises the first exception of class MPI_ERR_REVOKED has completed in a concurrent thread.
//end::MPI_Comm_is_revoked[]

//tag::MPI_Comm_get_failed[]
*MPI_Comm_get_failed* returns the group of MPI processes from a communicator that are known to have failed by the calling process.
This operation is local. The `failedgrp` may be empty, equal to MPI_GROUP_EMPTY. MPI makes no assumption about asynchronous progress of failure detection; a valid MPI implementation may update the group of locally known failed processes only when it enters a procedure that must raise a fault tolerance error. It is possible that only the calling process has detected the reported failure.
//end::MPI_Comm_get_failed[]

//tag::MPI_Comm_ack_failed[]
*MPI_Comm_ack_failed* acknowledges locally notified process failures on a communicator.
This operation is local. Supplying 0 in `num_to_ack` queries for the number of currently acknowledged process failures without side effect. After a process failure is acknowledged, unmatched MPI_ANY_SOURCE receive operations on the same communicator proceed without raising errors due to the acknowledged failure. Calling *MPI_Comm_ack_failed* on a communicator with failed processes has no effect on collective operations.
//end::MPI_Comm_ack_failed[]

//tag::MPI_Comm_accept[]
*MPI_Comm_accept* establishes communication with a client by accepting a connection on a port.
This operation is nonlocal and collective over the calling communicator. It returns an inter-communicator that allows communication with the client, where the local group contains the accepting processes and the remote group contains the connecting processes. The `port_name` must have been established through a call to *MPI_Open_port*. The `info` argument may be used to provide directives that influence the behavior of the call.
//end::MPI_Comm_accept[]

//tag::MPI_Comm_connect[]
*MPI_Comm_connect* establishes communication with a server specified by `port_name`.
This operation is nonlocal and collective over the calling communicator. It returns an inter-communicator in which the remote group participated in an *MPI_Comm_accept*. If the named port does not exist or has been closed, an error of class MPI_ERR_PORT is raised. If the port exists but does not have a pending *MPI_Comm_accept*, the connection attempt will eventually time out after an implementation-defined time, or succeed when the server calls *MPI_Comm_accept*; in the case of a time out, an error of class MPI_ERR_PORT is raised. MPI provides no guarantee of fairness in servicing connection attempts, meaning connection attempts are not necessarily satisfied in the order they were initiated and competition from other connection attempts may prevent a particular connection attempt from being satisfied.
//end::MPI_Comm_connect[]

//tag::MPI_Comm_disconnect[]
*MPI_Comm_disconnect* waits for all decoupled MPI activities on `comm` to complete internally, deallocates the communicator object, and sets the handle to MPI_COMM_NULL.
This operation is nonlocal and collective. It may not be called with MPI_COMM_WORLD or MPI_COMM_SELF. *MPI_Comm_disconnect* may be called only if all communication is complete and matched, so that buffered data can be delivered to its destination; all request handles associated with `comm` must be freed for nonblocking operations, and must be inactive or freed for persistent or partitioned operations. After calling *MPI_Comm_disconnect*, freeing or starting an inactive persistent request handle for a communication operation on `comm` is erroneous. To disconnect two processes, it may be necessary to call *MPI_Comm_disconnect*, *MPI_Win_free*, and *MPI_File_close* to remove all communication paths between the two processes.
//end::MPI_Comm_disconnect[]

//tag::MPI_T_init_thread[]
*MPI_T_init_thread* initializes the MPI tool information interface and its thread environment.
Calling *MPI_T_init_thread* when the interface is already initialized has no effect beyond increasing the reference count. The `required` parameter specifies the desired thread support level and `provided` returns the actual level supported by the implementation. If *MPI_T_init_thread* is called before *MPI_Init_thread* or *MPI_Session_init*, the requested and provided thread levels may influence the behavior and return values of those functions, and the same is true for the reverse order.
//end::MPI_T_init_thread[]

//tag::MPI_T_finalize[]
*MPI_T_finalize* finalizes the use of the MPI tool information interface.
This operation is local and may be called as often as *MPI_T_init_thread* has been called up to the current point of execution. As long as the number of calls to *MPI_T_finalize* is smaller than the number of calls to *MPI_T_init_thread*, the interface remains initialized and calls to its routines are permissible. At the end of program execution, unless *MPI_Abort* is called, an application must have called *MPI_T_init_thread* and *MPI_T_finalize* an equal number of times.
//end::MPI_T_finalize[]

//tag::MPI_T_enum_get_info[]
*MPI_T_enum_get_info* retrieves the number of items and the name of a specified enumeration type.
This operation is local. The enumeration must represent at least one value and the returned name must be unique with respect to all other enumeration names used by the MPI implementation.
//end::MPI_T_enum_get_info[]

//tag::MPI_T_enum_get_item[]
*MPI_T_enum_get_item* retrieves the name and value of an enumeration item at a specified index.
This operation is local. The returned name must be at least one character in length and must be unique with respect to all other item names within the same enumeration.
//end::MPI_T_enum_get_item[]

//tag::MPI_T_cvar_get_num[]
*MPI_T_cvar_get_num* returns the number of control variables exported by the MPI implementation.
This operation is local. The number of control variables may increase during the execution of an MPI application when new variables become available through dynamic loading; however, variable indices are not permitted to change and variables are not permitted to be deleted once added. Users are recommended to note that while indices and variable properties are guaranteed not to change during a particular run, no such guarantee is provided between runs.
//end::MPI_T_cvar_get_num[]

//tag::MPI_T_cvar_get_info[]
*MPI_T_cvar_get_info* retrieves metadata for a control variable at a specified index.
After a successful call to *MPI_T_cvar_get_info* for a particular variable, subsequent calls querying information about the same variable must return the same information. If any OUT parameter is a NULL pointer, the implementation ignores the parameter and does not return a value for it.
//end::MPI_T_cvar_get_info[]

//tag::MPI_T_cvar_get_index[]
*MPI_T_cvar_get_index* retrieves the index of a control variable given a known variable name.
This operation is local. The `name` parameter is a null-terminated string provided by the caller, and if `name` does not match the name of any control variable provided by the implementation at the time of the call, the function returns MPI_T_ERR_INVALID_NAME.
//end::MPI_T_cvar_get_index[]

//tag::MPI_T_cvar_handle_alloc[]
*MPI_T_cvar_handle_alloc* allocates a handle for a control variable and binds it to an MPI object.
The `obj_handle` argument is ignored if *MPI_T_cvar_get_info* returned MPI_T_BIND_NO_OBJECT for this control variable. It is erroneous to provide a `cvar_index` value outside the range 0 to num_cvar-1, or to provide a bound MPI object whose type is inconsistent with the bind type returned by *MPI_T_cvar_get_info*. The `count` may differ based on the MPI object to which the control variable is bound, and predefined MPI object handles are recommended to be stored in a local variable with the address of that local variable passed into *MPI_T_cvar_handle_alloc*.
//end::MPI_T_cvar_handle_alloc[]

//tag::MPI_T_cvar_handle_free[]
*MPI_T_cvar_handle_free* frees a control variable handle and its associated resources.
This operation is local. On a successful return, the `handle` is set to MPI_T_CVAR_HANDLE_NULL.
//end::MPI_T_cvar_handle_free[]

//tag::MPI_T_cvar_read[]
*MPI_T_cvar_read* queries the value of a control variable and stores the result in a user-provided buffer.
This operation is local. Users are recommended to ensure that the buffer is of the appropriate size to hold the entire value of the control variable, based on the datatype and count returned by prior corresponding calls to *MPI_T_cvar_get_info* and *MPI_T_cvar_handle_alloc*.
//end::MPI_T_cvar_read[]

//tag::MPI_T_cvar_write[]
*MPI_T_cvar_write* sets the value of a control variable identified by `handle` to the data stored in `buf`.
This operation is local. If the variable cannot be changed at the time the call is made, the function returns MPI_T_ERR_CVAR_SET_NOT_NOW if there may be a later time at which the variable could be set, or MPI_T_ERR_CVAR_SET_NEVER if the variable cannot be set for the remainder of the application's execution. For variables with global or group scope, write calls are required to be issued by the user in all connected MPI processes or all MPI processes in the group, and users are required to ensure that writes in all participating processes are consistent.
//end::MPI_T_cvar_write[]

//tag::MPI_T_pvar_get_num[]
*MPI_T_pvar_get_num* returns the number of performance variables exported by the MPI implementation.
This operation is local. The number of performance variables may increase during execution when new variables become available through dynamic loading; however, variable indices are not permitted to change and variables are not permitted to be deleted once added. Applications may note that while indices and variable properties are guaranteed not to change during a particular run, no such guarantee is provided between runs.
//end::MPI_T_pvar_get_num[]

//tag::MPI_T_pvar_get_info[]
*MPI_T_pvar_get_info* retrieves metadata for a performance variable at a specified index.
After a successful call to *MPI_T_pvar_get_info* for a particular variable, subsequent calls querying information about the same variable must return the same information. If any OUT parameter is a NULL pointer, the implementation ignores the parameter and does not return a value for it. The `pvar_index` value is erroneous if outside the range 0 to `num_pvar`-1.
//end::MPI_T_pvar_get_info[]

//tag::MPI_T_pvar_get_index[]
*MPI_T_pvar_get_index* retrieves the index of a performance variable given a known variable name and class.
This operation is local. If `name` does not match the name of any performance variable of the specified `var_class` provided by the implementation at the time of the call, the function returns MPI_T_ERR_INVALID_NAME.
//end::MPI_T_pvar_get_index[]

//tag::MPI_T_pvar_session_create[]
*MPI_T_pvar_session_create* creates a new performance experiment session for accessing performance variables.
This operation is local. Starting, stopping, reading, writing, or resetting a variable in one performance experiment session does not influence whether a variable is started, stopped, read, written, or reset in another performance experiment session.
//end::MPI_T_pvar_session_create[]

//tag::MPI_T_pvar_session_free[]
*MPI_T_pvar_session_free* frees an existing performance experiment session.
This operation is local. Calls to the MPI tool information interface can no longer be made within the context of the session after it is freed. On a successful return, the `pe_session` identifier is set to MPI_T_PVAR_SESSION_NULL.
//end::MPI_T_pvar_session_free[]

//tag::MPI_T_pvar_handle_alloc[]
*MPI_T_pvar_handle_alloc* allocates a handle for a performance variable and binds it to an MPI object within a performance experiment session.
This operation is local. The `obj_handle` argument is ignored if *MPI_T_pvar_get_info* returned MPI_T_BIND_NO_OBJECT for this performance variable. It is erroneous to provide a `pvar_index` value outside the range 0 to `num_pvar`-1, or to provide a bound MPI object whose type is inconsistent with the bind type returned by *MPI_T_pvar_get_info*. The `count` may differ based on the MPI object to which the performance variable is bound, and predefined MPI object handles are recommended to be stored in a local variable with the address of that local variable passed into *MPI_T_pvar_handle_alloc*.
//end::MPI_T_pvar_handle_alloc[]

//tag::MPI_T_pvar_handle_free[]
*MPI_T_pvar_handle_free* frees a performance variable handle and its associated resources within a performance experiment session.
This operation is local. On a successful return, the `handle` is set to MPI_T_PVAR_HANDLE_NULL. If the `handle` argument is not associated with the `pe_session` argument, MPI_T_ERR_INVALID_HANDLE is returned.
//end::MPI_T_pvar_handle_free[]

//tag::MPI_T_pvar_start[]
*MPI_T_pvar_start* starts the performance variable identified by `handle` within the session identified by `pe_session`.
This operation is local. If MPI_T_PVAR_ALL_HANDLES is passed in `handle`, the MPI implementation attempts to start all variables within the session for which handles have been allocated; continuous variables and variables that are already started are ignored when MPI_T_PVAR_ALL_HANDLES is specified.
//end::MPI_T_pvar_start[]

//tag::MPI_T_pvar_stop[]
*MPI_T_pvar_stop* stops the performance variable identified by `handle` within the session identified by `pe_session`.
This operation is local. If MPI_T_PVAR_ALL_HANDLES is passed in `handle`, the MPI implementation attempts to stop all variables within the session for which handles have been allocated; continuous variables and variables that are already stopped are ignored when MPI_T_PVAR_ALL_HANDLES is specified.
//end::MPI_T_pvar_stop[]

//tag::MPI_T_pvar_read[]
*MPI_T_pvar_read* queries the value of a performance variable and stores the result in a user-provided buffer.
This operation is local. It is erroneous to use MPI_T_PVAR_ALL_HANDLES as the `handle` argument.
//end::MPI_T_pvar_read[]

//tag::MPI_T_pvar_write[]
*MPI_T_pvar_write* attempts to write a value to a performance variable within a performance experiment session.
This operation is local. If the variable cannot be changed, the function returns MPI_T_ERR_PVAR_NO_WRITE. It is erroneous to use MPI_T_PVAR_ALL_HANDLES as the `handle` argument.
//end::MPI_T_pvar_write[]

//tag::MPI_T_pvar_reset[]
*MPI_T_pvar_reset* sets a performance variable to its starting value within a performance experiment session.
This operation is local. If the variable cannot be changed, the function returns MPI_T_ERR_PVAR_NO_WRITE. If MPI_T_PVAR_ALL_HANDLES is passed in `handle`, the MPI implementation attempts to reset all variables within the session for which handles have been allocated; read-only variables are ignored when MPI_T_PVAR_ALL_HANDLES is specified.
//end::MPI_T_pvar_reset[]

//tag::MPI_T_pvar_readreset[]
*MPI_T_pvar_readreset* atomically reads the value of a performance variable and resets it to its starting value.
This operation is local and combines the functionality of *MPI_T_pvar_read* and *MPI_T_pvar_reset* with the same semantics as if these two calls were called separately. If the variable cannot be read and reset atomically, the function returns MPI_T_ERR_PVAR_NO_ATOMIC. MPI_T_PVAR_ALL_HANDLES is not permitted as the `handle` argument.
//end::MPI_T_pvar_readreset[]

//tag::MPI_T_source_get_num[]
*MPI_T_source_get_num* returns the number of event sources exported by the MPI implementation.
This operation is local. The number of event sources may increase during the execution of an MPI process; however, source indices are not permitted to change and sources are not permitted to be deleted once made visible to the user.
//end::MPI_T_source_get_num[]

//tag::MPI_T_source_get_info[]
*MPI_T_source_get_info* retrieves metadata for an event source at a specified index.
This operation is local. The `ordering` argument indicates whether event callbacks of the source will be invoked in chronological order, with timestamps monotonically increasing. The `ticks_per_second` argument returns the number of ticks elapsed in one second for the timer used by the source, and `max_ticks` returns the largest timestamp value before overflow occurs.
//end::MPI_T_source_get_info[]

//tag::MPI_T_source_get_timestamp[]
*MPI_T_source_get_timestamp* obtains a current timestamp from a specified event source.
This operation is local and returns MPI_SUCCESS with a current timestamp in `timestamp` if the source supports ad-hoc generation of timestamps. The function returns MPI_T_ERR_INVALID_INDEX if `source_index` does not identify a valid source, or MPI_T_ERR_NOT_SUPPORTED if the source does not support ad-hoc generation of timestamps.
//end::MPI_T_source_get_timestamp[]

//tag::MPI_T_event_get_num[]
*MPI_T_event_get_num* returns the number of event types exported by the MPI implementation.
This operation is local. The number of event types may increase during the execution of an MPI process; however, event type indices are not permitted to change and event types are not permitted to be deleted once made visible to the user.
//end::MPI_T_event_get_num[]

//tag::MPI_T_event_get_info[]
*MPI_T_event_get_info* retrieves metadata for an event type at a specified index.
This operation is local. After a successful call to *MPI_T_event_get_info* for a particular event type, subsequent calls querying information about the same event type must return the same information. If any INOUT or OUT argument is a NULL pointer, the implementation ignores the argument and does not return a value for it. The function returns MPI_T_ERR_INVALID_INDEX if `event_index` does not match a valid event type index provided by the implementation at the time of the call.
//end::MPI_T_event_get_info[]

//tag::MPI_T_event_get_index[]
*MPI_T_event_get_index* returns the index of an event type identified by a known event type name.
This operation is local. The `name` parameter is a null-terminated string provided by the caller, and if `name` does not match the name of any event type provided by the implementation at the time of the call, the function returns MPI_T_ERR_INVALID_NAME.
//end::MPI_T_event_get_index[]

//tag::MPI_T_event_handle_alloc[]
*MPI_T_event_handle_alloc* creates a registration handle for an event type and optionally binds it to an MPI object.
This operation is local. The `obj_handle` argument is ignored if *MPI_T_event_get_info* returned MPI_T_BIND_NO_OBJECT for this event type. Hints for the handle allocation may be passed to the MPI implementation via the `info` argument.
//end::MPI_T_event_handle_alloc[]

//tag::MPI_T_event_handle_set_info[]
*MPI_T_event_handle_set_info* updates the hints of an event-registration handle using the hints provided in `info`.
This operation is local and has no effect on previously set or defaulted hints that are not specified by `info`, nor on hints that are specified by `info` but ignored by the MPI implementation. Some info items that an implementation uses when creating an event-registration handle cannot easily be changed once the handle is created, so an implementation may ignore hints in this call that it would have accepted in a handle allocation call. Users may call *MPI_T_event_handle_get_info* to determine whether info changes were ignored by the implementation.
//end::MPI_T_event_handle_set_info[]

//tag::MPI_T_event_handle_get_info[]
*MPI_T_event_handle_get_info* returns a new info object containing the hints of an event-registration handle.
This operation is local. The returned `info_used` contains all hints that are supported by the implementation and have default values specified, any user-supplied hints that were not ignored by the implementation, and any additional hints set by the implementation. If no such hints exist, a handle to a newly created info object containing no key/value pairs is returned. The user is responsible for freeing `info_used` via *MPI_Info_free*.
//end::MPI_T_event_handle_get_info[]

//tag::MPI_T_event_callback_set_info[]
*MPI_T_event_callback_set_info* updates the hints of a callback function registered for a specific callback safety level of an event-registration handle.
A call to this procedure has no effect on previously set or defaulted hints that are not specified by `info`, and has no effect on hints that are specified by `info` but ignored by the MPI implementation.
//end::MPI_T_event_callback_set_info[]

//tag::MPI_T_event_register_callback[]
*MPI_T_event_register_callback* associates a user-defined callback function with an event-registration handle.
This operation is local. A user may register multiple callback functions for a given event-registration handle, potentially specifying one for each callback safety level. Registering a callback function for a specific callback safety level overwrites any previously-registered callback function and info object for that safety level; if `event_cb_function` is the NULL pointer, the existing association for that callback safety level is removed. When an event is triggered, the implementation selects from all registered callbacks the callback with the lowest safety level valid in the context in which the callback is invoked; in situations where the required callback safety level exceeds the highest level for which a callback function is registered, the event instance is dropped. Callback functions with the highest callback safety guarantees are recommended to be registered before any further registrations for lower callback safety guarantees, to avoid dropped events due to insufficient callback safety guarantees.
//end::MPI_T_event_register_callback[]

//tag::MPI_T_event_cb_function[]
*MPI_T_event_cb_function* is the callback function type invoked by the MPI implementation when an event is raised.
The `event_instance` handle is only valid inside the corresponding invocation of the callback function to which it is passed. If the callback is invoked with `cb_safety` of MPI_T_CB_REQUIRE_THREAD_SAFE, the callback must be reentrant and thread-safe, allowing its execution to be interrupted by or happen concurrently with any other callback including itself. If the callback is invoked with `cb_safety` of MPI_T_CB_REQUIRE_ASYNC_SIGNAL_SAFE, the callback must additionally meet the safety requirements needed to support invocations from asynchronous contexts such as signal handlers.
//end::MPI_T_event_cb_function[]

//tag::MPI_T_event_callback_get_info[]
*MPI_T_event_callback_get_info* returns a new info object containing the hints of a callback function registered for a specific callback safety level of an event-registration handle.
This operation is local. The returned `info_used` contains all hints that are supported by the implementation and have default values specified, any user-supplied hints that were not ignored by the implementation, and any additional hints set by the implementation. If no such hints exist, a handle to a newly created info object containing no key/value pairs is returned. The user is responsible for freeing `info_used` via *MPI_Info_free*.
//end::MPI_T_event_callback_get_info[]

//tag::MPI_T_event_handle_free[]
*MPI_T_event_handle_free* frees an event-registration handle and stops the MPI implementation from raising events for that registration.
This operation is local and returns MPI_SUCCESS when deallocation is initiated successfully, or MPI_T_ERR_INVALID_HANDLE if `event_registration` does not match a valid allocated event-registration handle. //tag::MPI_Alltoall[]

//tag::MPI_Finalize[]
*MPI_Finalize* cleans up all MPI state associated with the World Process Model.
This operation is nonlocal and collective over all connected processes; if no processes were spawned, accepted, or connected then this means over MPI_COMM_WORLD, otherwise it is collective over the union of all processes that have been and continue to be connected. Before invoking *MPI_Finalize*, the process must perform all MPI calls needed to complete its involvement in MPI communications, locally complete all MPI operations it initiated, and execute matching calls needed to complete MPI communications initiated by other processes. All message handles must be received and all request handles must be freed for nonblocking operations, or inactive or freed for persistent or partitioned operations. When using threads, *MPI_Finalize* is required to be called on the main thread that initialized MPI, and only after all process threads have completed their MPI calls with no pending communication or I/O operations. The call first executes the equivalent of *MPI_Comm_free* on MPI_COMM_SELF, invoking delete callback functions on all keys associated with MPI_COMM_SELF in the reverse order they were set. If the calling process is a member of `group`, then `newcomm` is a communicator with `group` as its associated group; if the calling process is not a member of `group`, the call is a local operation and MPI_COMM_NULL is returned. If multiple threads at a given MPI process perform concurrent *MPI_Comm_create_group* operations, the user must distinguish these operations by providing different `tag` or `comm` arguments.
//end::MPI_Comm_create_group[]

//tag::MPI_Comm_dup[]
*MPI_Comm_dup* duplicates an existing communicator with associated key values, topology information, and error handlers.
This operation is nonlocal and collective over the group or groups associated with `comm`. The new communicator `newcomm` has the same group or groups, same topology, same error handlers, and any copied cached information, but a new context. For each key value, the respective copy callback function determines the attribute value associated with this key in the new communicator. The newly created communicator will have no buffer attached. This call is valid even if there are pending point-to-point communication operations or decoupled MPI activities involving the communicator `comm`. This call applies to both intra-communicators and inter-communicators, and may be used to provide a parallel library with a duplicate communication space that has the same properties as the original communicator.
//end::MPI_Comm_dup[]

//tag::MPI_COMM_DUP_FN[]
*MPI_COMM_DUP_FN* is a predefined attribute copy callback function that duplicates an attribute value.
This function sets `flag` = 1, returns the value of `attribute_val_in` in `attribute_val_out`, and returns MPI_SUCCESS. This function may be specified from either C or Fortran.
//end::MPI_COMM_DUP_FN[]

//tag::MPI_Comm_create[]
*MPI_Comm_create* creates a new communicator from a subset of the group of an existing communicator.
This operation is collective and nonlocal; all MPI processes in the group of `comm` must call *MPI_Comm_create*. If an MPI process calls with a nonempty `group`, all MPI processes in that `group` must call with the same `group` argument containing the same MPI processes in the same order. The set of groups specified across all MPI processes must be disjoint. If the calling MPI process is a member of `group`, `newcomm` is returned with `group` as its associated group; otherwise, including the case where `group` is `MPI_GROUP_EMPTY`, `MPI_COMM_NULL` is returned. *MPI_Comm_create* may be used to subset a group of MPI processes for the purpose of separate MIMD computation with separate communication space.

This operation is local. The union contains all elements of `group1`, followed by all elements of `group2` not in `group1`, with the order of MPI processes determined primarily by order in `group1` and then by order in `group2`. The resulting `newgroup` may be MPI_GROUP_EMPTY.

//tag::MPI_Group_intersection[]
*MPI_Group_intersection* creates a new group from the intersection of two existing groups.

//tag::MPI_Group_difference[]
*MPI_Group_difference* creates a new group from the set difference of two existing groups.

//end::MPI_Group_difference[]

//tag::MPI_Group_incl[]
*MPI_Group_incl* creates a new group from a subset of an existing group, with MPI processes ordered according to a specified array of ranks.

//tag::MPI_Mprobe[]
*MPI_Mprobe* is a blocking matching probe that returns only after a matching message has been found.
This operation is nonlocal and returns a message handle that may only be received with *MPI_Mrecv* or *MPI_Imrecv*. The `source` argument may be `MPI_ANY_SOURCE` and the `tag` argument may be `MPI_ANY_TAG`, but a specific communicator must be provided. *MPI_Mrecv* receives a message that was previously matched by a matching probe operation.

//tag::MPI_Win_start[]
*MPI_Win_start* opens an RMA access epoch for the specified window.
RMA calls issued on `win` during this epoch are permitted to access only windows at MPI processes in `group`. Each MPI process in `group` must issue a matching call to *MPI_Win_post*. RMA accesses to each target window are delayed, if necessary, until the target process executes the matching call to *MPI_Win_post*. This operation is nonlocal and may delay its return until the corresponding calls to *MPI_Win_post* have occurred. To write portable deadlock-free programs, users are recommended to assume that *MPI_Win_start* may delay its return until the corresponding calls to *MPI_Win_post* have occurred.
//end::MPI_Win_start[]

This operation is nonlocal and returns data from the target buffer to the result buffer before accumulating origin data into the target using the specified operator. When `target_rank` is `MPI_PROC_NULL`, the operation becomes a no-op. If `op` is `MPI_NO_OP`, the `origin_addr`, `origin_count`, and `origin_datatype` arguments are ignored and the target buffer is not updated.

//tag::MPI_Compare_and_swap[]
*MPI_Compare_and_swap* performs a remote atomic compare-and-swap operation on one element of a window.
This operation is nonlocal and compares one element at the origin with one element at the target, replacing the target value with the origin value only if the compare buffer and target buffer are identical. The original target value is returned in the result buffer. The `origin_addr` and `result_addr` buffers must be disjoint. If `target_rank` is MPI_PROC_NULL, no operation is performed. The `datatype` argument must be a predefined datatype belonging to one of the following categories: C integer, Fortran integer, Logical, Multi-language types, or Byte.
//end::MPI_Compare_and_swap[]

//tag::MPI_Put[]
*MPI_Put* is a nonblocking RMA communication call that transfers data from the origin process memory to a target process window.

A file handle may have at most one active split collective operation at any time. It is erroneous to access the buffer passed to a split collective data access operation, or to use that buffer as the source or target of other communications, between the begin and end calls.
//end::MPI_File_read_at_all_begin[]

//tag::MPI_File_read_at_all_end[]
*MPI_File_read_at_all_end* completes a split collective read from a file initiated by *MPI_File_read_at_all_begin*.
This operation is nonlocal and collective over the group of processes that participated in the collective open, following the ordering rules for collective calls. Each end call matches the preceding begin call for the same collective operation, and when an end call is made, exactly one unmatched begin call for the same operation must precede it. For consistency semantics, a matched pair of split collective data access operations compose a single data access. In a multithreaded implementation, any split collective begin and end operation called by a process must be called from the same thread. Split collective routines must specify a `buf` in both the begin and end routines.
//end::MPI_File_read_at_all_end[]

This operation is nonlocal and collective over the group of processes that participated in the collective open, following the ordering rules for collective calls. For consistency semantics, a matched pair of split collective data access operations compose a single data access. In a multithreaded implementation, any split collective begin and end operation called by a process must be called from the same thread. Split collective routines must specify a `buf` in both the begin and end routines.
//end::MPI_File_write_at_all_end[]

//tag::MPI_File_read_all_end[]
*MPI_File_read_all_end* completes a split collective read using the individual file pointer initiated by *MPI_File_read_all_begin*.
This operation is collective over the group of processes that participated in the collective open and follows the ordering rules for collective calls. Each end call matches the preceding begin call for the same collective operation, and when an end call is made, exactly one unmatched begin call for the same operation must precede it. For consistency semantics, a matched pair of split collective data access operations compose a single data access. In a multithreaded implementation, the begin and end operations must be called from the same thread. Split collective operations do not match with regular collective operations; an *MPI_File_read_all_begin*/*MPI_File_read_all_end* pair on one process may not be matched with *MPI_File_read_all* on another process.
//end::MPI_File_read_all_end[]

//tag::MPI_File_read_ordered_end[]
*MPI_File_read_ordered_end* completes a split collective read using the shared file pointer initiated by *MPI_File_read_ordered_begin*.
This operation is nonlocal and collective over the group of processes that participated in the collective open. End calls follow the ordering rules for collective calls, and each end call matches the preceding begin call for the same collective operation. In a multithreaded implementation, the begin and end operations must be called from the same thread. For consistency semantics, a matched pair of split collective data access operations compose a single data access. Split collective operations do not match with regular collective operations; an *MPI_File_read_ordered_begin*/*MPI_File_read_ordered_end* pair on one process does not match *MPI_File_read_ordered* on another process.
//end::MPI_File_read_ordered_end[]

//tag::MPI_File_write_ordered_begin[]
*MPI_File_write_ordered_begin* begins a split collective write operation using the shared file pointer with accesses ordered by process rank.
This operation is nonlocal and collective over the group of processes that participated in the collective open, and it may or may not return before all MPI processes in the group have called the routine. Accesses to the file are in the order determined by the ranks of the processes within the group; for each process, the location in the file at which data is accessed is the position at which the shared file pointer would be after all processes with lower ranks had accessed their data. In a multithreaded implementation, any split collective begin and end operation called by a process must be called from the same thread. A file handle may have at most one active split collective operation at any time, and no collective I/O operations are permitted on a file handle concurrently with a split collective access on that file handle. This operation is nonlocal and collective over the group of processes that participated in the collective open. End calls follow the ordering rules for collective calls, and each end call matches the preceding begin call for the same collective operation. In a multithreaded implementation, the begin and end operations must be called from the same thread. //tag::MPI_Register_datarep[]
*MPI_Register_datarep* associates user-defined data conversion functions with a named data representation for use with *MPI_File_set_view*.
This operation is local and only registers the data representation for the calling MPI process. If `datarep` is already defined, an error in the class MPI_ERR_DUP_DATAREP is raised. The constants MPI_CONVERSION_FN_NULL or MPI_CONVERSION_FN_NULL_C may be passed as either conversion function argument, in which case MPI performs data access using native representation without invoking that conversion function. The conversion functions must be reentrant, and it is erroneous for conversion functions to call any collective routines or to free the `datatype` argument.
//end::MPI_Register_datarep[]

//tag::MPI_Datarep_extent_function[]
*MPI_Datarep_extent_function* is a callback function type used to compute the extent of a datatype in a user-defined file data representation.
The callback must return in `extent` the number of bytes required to store `datatype` in the file representation, and MPI will only invoke this callback with predefined datatypes employed by the user. If the extent cannot be represented in `extent`, the callback function shall set `extent` to `MPI_UNDEFINED`, which causes MPI to raise an error of class MPI_ERR_VALUE_TOO_LARGE.
//end::MPI_Datarep_extent_function[]

//tag::MPI_CONVERSION_FN_NULL[]
*MPI_CONVERSION_FN_NULL* is a predefined constant that may be passed as either the `read_conversion_fn` or `write_conversion_fn` argument to *MPI_Register_datarep*.
When this constant is used, MPI will not invoke the corresponding conversion function and will perform data access using native data representation.
//end::MPI_CONVERSION_FN_NULL[]

//tag::MPI_File_sync[]
*MPI_File_sync* causes all previous writes to a file by the calling process to be transferred to the storage device.
This operation is collective over the group of processes that opened the file. If other processes have made updates to the storage device, all such updates become visible to subsequent reads of `fh` by the calling process. *MPI_File_sync* may be necessary to ensure sequential consistency when accessing a file from file handles created by different collective opens. Users are required to ensure that all nonblocking requests and split collective operations on `fh` have completed before calling *MPI_File_sync*.
//end::MPI_File_sync[]

//tag::MPI_Win_allocate_shared[]
*MPI_Win_allocate_shared* allocates shared memory and creates a window object for one-sided communication.
This operation is collective and nonlocal over the group of `comm`. On each MPI process, it allocates memory of at least `size` bytes that is shared among all MPI processes in `comm`, returning a pointer to the locally allocated segment and a window handle that can be used to perform RMA operations. An MPI process may specify `size` = 0, which is valid. The allocated memory is contiguous across MPI processes in rank order unless the info key `alloc_shared_noncontig` is set to true; users may use this key to allow the library to optimize memory layout. For contiguous shared memory allocations, the default memory alignment requirements apply to the start of the contiguous memory returned to the first MPI process with nonzero `size`; for noncontiguous allocations, alignment requirements apply to all MPI processes with nonzero `size`.
//end::MPI_Win_allocate_shared[]

//tag::MPI_Win_shared_query[]
*MPI_Win_shared_query* queries the process-local address for remote memory segments created with *MPI_Win_allocate_shared*, *MPI_Win_allocate*, or *MPI_Win_create*.
When `rank` is `MPI_PROC_NULL`, the returned `baseptr`, `disp_unit`, and `size` are those of the memory segment belonging to the MPI process with the lowest rank in the shared memory domain that specified `size` > 0. When the remote memory segment corresponding to a particular MPI process cannot be accessed directly, `size` = 0 is returned. A consistent view may be created in the unified memory model by utilizing window synchronization functions or explicitly completing outstanding store accesses.
//end::MPI_Win_shared_query[]

//tag::MPI_Win_create_dynamic[]
*MPI_Win_create_dynamic* creates a window object for one-sided communication that allows dynamic control over which memory is exposed.
This operation is collective and nonlocal over the group of `comm`. The window is returned without memory attached; existing process memory may be attached using *MPI_Win_attach* and detached using *MPI_Win_detach*. For dynamic windows, the `target_disp` argument to RMA operations is the address at the target, and users are recommended to use *MPI_Get_address* at the target process to determine target memory locations and communicate these addresses to the origin process. Memory at the target cannot be accessed with this window until that memory has been attached using *MPI_Win_attach*, and users are responsible for ensuring that *MPI_Win_attach* at the target has returned before an MPI process attempts to target that memory with an RMA operation.
//end::MPI_Win_create_dynamic[]

//tag::MPI_Win_attach[]
*MPI_Win_attach* attaches a local memory region to a dynamic window for remote access.
This operation is local and not collective. It is erroneous to attach overlapping memory concurrently within the same window. Attaching large regions of memory is not recommended in portable programs, and the user is responsible for ensuring that *MPI_Win_attach* at the target has returned before an MPI process attempts to target that memory with an RMA operation.
//end::MPI_Win_attach[]

//tag::MPI_Win_detach[]
*MPI_Win_detach* detaches a previously attached memory region from a dynamic window.
This operation is local and not collective. The `base` and `win` arguments must match the arguments passed to a previous call to *MPI_Win_attach*. After memory has been detached, it may not be the target of an RMA operation on that window unless re-attached with *MPI_Win_attach*. Memory is recommended to be detached before it is freed by the user.
//end::MPI_Win_detach[]

//tag::MPI_Win_free[]
*MPI_Win_free* frees the window object and returns a null handle equal to `MPI_WIN_NULL`.
This operation is collective over the group associated with `win` and is nonlocal. *MPI_Win_free* may be invoked by an MPI process only after it has completed its involvement in RMA communications on the window; for example, after calling *MPI_Win_fence*, *MPI_Win_wait* to match a previous call to *MPI_Win_post*, *MPI_Win_complete* to match a previous call to *MPI_Win_start*, or *MPI_Win_unlock* to match a previous call to *MPI_Win_lock*. *MPI_Win_free* delays its return until all accesses to the local window using passive target synchronization have completed, making it synchronizing unless the window was created with the `no_locks` info key set to true. The memory associated with windows created by *MPI_Win_create* may be freed after the call returns. If the window was created with *MPI_Win_allocate* or *MPI_Win_allocate_shared*, *MPI_Win_free* will free the memory that was allocated. Freeing a window created with *MPI_Win_create_dynamic* detaches all associated memory.
//end::MPI_Win_free[]

//tag::MPI_Win_set_info[]
*MPI_Win_set_info* updates the hints of a window using the hints provided in an info object.
This operation is collective over the group of `win`. The entries in the `info` object may be different on each MPI process, but any info entries that an implementation requires to be the same on all MPI processes must appear with the same value in each MPI process's info object. This operation has no effect on previously set or defaulted hints that are not specified by `info`, nor on hints that are specified by `info` but ignored by the MPI implementation. Some info items that an implementation uses when creating a window cannot easily be changed once the window has been created, so an implementation may ignore hints in this call that it would have accepted in a window creation call. *MPI_Win_get_info* may be used to determine whether info changes were ignored by the implementation.
//end::MPI_Win_set_info[]

//tag::MPI_Win_get_info[]
*MPI_Win_get_info* returns a new info object containing the hints of the window associated with `win`.
The returned `info_used` contains all hints that are supported by the implementation and have default values specified, any user-supplied hints that were not ignored by the implementation, and any additional hints that were set by the implementation. If no such hints exist, a handle to a newly created info object containing no key/value pair is returned. The user is responsible for freeing `info_used` via *MPI_Info_free*.
//end::MPI_Win_get_info[]

//tag::MPI_Win_fence[]
*MPI_Win_fence* synchronizes RMA communication operations on a window.
This operation is collective over the group of `win` and is usually nonlocal; however, a call with the `MPI_MODE_NOPRECEDE` `assert` is not necessarily synchronizing. All RMA operations on `win` originating at a given process and started before the fence call will complete at that process and at their target before the fence call returns. RMA operations on `win` started by an origin process after the fence call returns will access their target window only after *MPI_Win_fence* has been called by the target process. Calls to *MPI_Win_fence* are recommended to both precede and follow calls to RMA communication procedures that are synchronized with fence calls.
//end::MPI_Win_fence[]

//tag::MPI_Get[]
*MPI_Get* is a nonblocking RMA communication call that transfers data from the target process window to the origin process memory.
This operation is nonlocal and completes at the origin when a subsequent synchronization call is executed. If `target_rank` is `MPI_PROC_NULL`, the operation is a no-op. The `origin_datatype` may not specify overlapping entries in the origin buffer, the target buffer must be contained within the target window or within attached memory in a dynamic window, and the copied data must fit without truncation in the origin buffer.
//end::MPI_Get[]

//tag::MPI_Accumulate[]
*MPI_Accumulate* is a nonblocking RMA communication call that combines data from the origin buffer with data in the target window using a specified reduction operator.
This operation is nonlocal and completes at the origin when a subsequent synchronization call such as *MPI_Win_fence*, *MPI_Win_complete*, *MPI_Win_flush*, or *MPI_Win_unlock* is executed. If `target_rank` is `MPI_PROC_NULL`, the operation is a no-op. Concurrent accumulate operations to the same location with the same predefined datatype are permitted and execute atomically on a per-element basis, with the outcome as if the updates occurred in some serial order. By default, accumulate operations from the same origin to overlapping target memory regions are ordered; the `accumulate_ordering` info key may be used to relax this ordering. Programs may use *MPI_Accumulate* with `MPI_REPLACE` for put-like behavior that permits concurrent updates to the same location.
//end::MPI_Accumulate[]

//tag::MPI_Fetch_and_op[]
*MPI_Fetch_and_op* is a nonblocking RMA communication call that atomically fetches data from a target window into a result buffer and accumulates a single element from an origin buffer into the target window using a specified reduction operator.
This operation is nonlocal and completes at the origin when a subsequent synchronization call such as *MPI_Win_fence*, *MPI_Win_complete*, *MPI_Win_flush*, or *MPI_Win_unlock* is executed. If `target_rank` is `MPI_PROC_NULL`, the operation is a no-op. If `MPI_NO_OP` is specified as the operator, the `origin_addr` argument is ignored and the target buffer is not updated. The operation is executed atomically, the `origin_addr` and `result_addr` buffers must be disjoint, and the `datatype` argument must be a predefined datatype.
//end::MPI_Fetch_and_op[]

//tag::MPI_Rput[]
*MPI_Rput* is a request-based nonblocking RMA communication call that transfers data from the origin process memory to a target process window and returns a request handle for tracking completion.
This operation is nonlocal and completion at the origin indicates the sender is free to update the origin buffer, but does not indicate that the data is available at the target window. If `target_rank` is `MPI_PROC_NULL`, the operation is a no-op but it is still necessary to close the RMA epoch with the synchronization method that opened the epoch. *MPI_Win_flush*, *MPI_Win_flush_all*, *MPI_Win_unlock*, or *MPI_Win_unlock_all* may be used when remote completion is required.
//end::MPI_Rput[]

//tag::MPI_Rget[]
*MPI_Rget* is a request-based RMA operation that transfers data from the target memory to the origin.
This operation is nonlocal and completion at the origin indicates that the data is available in the origin buffer. If `target_rank` is `MPI_PROC_NULL`, the operation is a no-op but it is still necessary to close the RMA epoch with the synchronization method that opened the epoch. If `origin_addr` points to memory attached to a window, the data becomes available in the private copy of this window.
//end::MPI_Rget[]

//tag::MPI_Raccumulate[]
*MPI_Raccumulate* is a request-based RMA operation that combines data from the origin buffer with data in the target window using a specified reduction operator and returns a request handle.
This operation is nonlocal and completion at the origin indicates the origin buffer is free to be updated, but does not indicate that the operation has completed at the target window. If `target_rank` is `MPI_PROC_NULL`, the operation is a no-op but it is still necessary to close the RMA epoch with the synchronization method that opened the epoch. Concurrent accumulate operations to the same location with the same predefined datatype are permitted and execute atomically on a per-element basis, with the outcome as if the updates occurred in some serial order. `MPI_NO_OP` is not permitted as the `op` argument.
//end::MPI_Raccumulate[]

//tag::MPI_Win_complete[]
*MPI_Win_complete* closes an RMA access epoch on `win` opened by a call to *MPI_Win_start*.
This operation is nonlocal and when the call returns, all RMA communication operations initiated on `win` during this epoch will have completed at the origin. All updates to shared memory in `win` through load/store accesses executed during this epoch will be visible at the target when the call returns. *MPI_Win_complete* enforces completion of preceding RMA operations and visibility of load/store accesses at the origin, but not at the target; a put or accumulate operation may not have completed at the target when it has completed at the origin.
//end::MPI_Win_complete[]

//tag::MPI_Win_post[]
*MPI_Win_post* opens an RMA exposure epoch for the local window associated with `win`.
This operation is local and returns before the exposure epoch is closed. Only MPI processes in `group` may access the window with RMA calls on `win` during this epoch, and each MPI process in `group` must issue a matching call to *MPI_Win_start*. If the `group` argument is empty, the call is a no-op and may be skipped.
//end::MPI_Win_post[]

//tag::MPI_Win_lock[]
*MPI_Win_lock* starts a passive target RMA access epoch that acquires a lock on a target process's window.
This operation is nonlocal and may delay its return until the lock on the target window has been acquired. Accesses protected by an exclusive lock acquired using `MPI_LOCK_EXCLUSIVE` will not be concurrent at the window site with other lock-protected accesses to the same window. Accesses protected by a shared lock acquired using `MPI_LOCK_SHARED` will not be concurrent at the window site with accesses protected by an exclusive lock to the same window. Multiple RMA access epochs with calls to *MPI_Win_lock* may occur simultaneously, but each access epoch must target a different MPI process. To write portable deadlock-free programs, users may assume that *MPI_Win_lock* delays its return until the desired lock on the window has been acquired.
//end::MPI_Win_lock[]

//tag::MPI_Win_lock_all[]
*MPI_Win_lock_all* starts a passive target RMA access epoch to all MPI processes in the window's group with a lock type of `MPI_LOCK_SHARED`.
During this epoch, the calling MPI process may access the window memory on all MPI processes in `win` using RMA operations. A window locked with *MPI_Win_lock_all* must be unlocked with *MPI_Win_unlock_all*. This routine is not collective; the "ALL" refers to a lock on all members of the group of the window. There may be additional overheads associated with using *MPI_Win_lock* and *MPI_Win_lock_all* concurrently on the same window; these overheads may be avoided by specifying the assertion `MPI_MODE_NOCHECK` when no other MPI process holds or will attempt to acquire a conflicting lock.
//end::MPI_Win_lock_all[]

//tag::MPI_Win_unlock[]
*MPI_Win_unlock* completes a passive target RMA access epoch started by *MPI_Win_lock*.
This operation is nonlocal and all RMA operations issued during the epoch will have completed both at the origin and at the target when the call returns. The update of a public window copy by put or accumulate operations is complete at the target as soon as the updating origin process executes *MPI_Win_unlock*. Locks may be used portably only in memory allocated by *MPI_Alloc_mem*, *MPI_Win_allocate*, *MPI_Win_allocate_shared*, or attached with *MPI_Win_attach*. It is erroneous to have a window locked and exposed in an exposure epoch concurrently. To write portable deadlock-free programs, users may assume that *MPI_Win_lock* delays its return until the desired lock on the window has been acquired.
//end::MPI_Win_unlock[]

//tag::MPI_Win_unlock_all[]
*MPI_Win_unlock_all* completes a shared passive target RMA access epoch started by *MPI_Win_lock_all* on `win`.
This operation is nonlocal and all RMA operations issued during the epoch will have completed both at the origin and at the target when the call returns. This routine is not collective; the "ALL" refers to unlocking the shared lock on all members of the group of the window. Locks may be used portably only in memory allocated by *MPI_Alloc_mem*, *MPI_Win_allocate*, *MPI_Win_allocate_shared*, or attached with *MPI_Win_attach*. It is erroneous to have a window locked and exposed in an exposure epoch concurrently.
//end::MPI_Win_unlock_all[]

//tag::MPI_Win_flush[]
*MPI_Win_flush* completes all outstanding RMA operations initiated by the calling process to the target process specified by `rank`.
This operation is nonlocal and all RMA operations on `win` initiated by the calling process to the target will have completed both at the origin and at the target when *MPI_Win_flush* returns.
//end::MPI_Win_flush[]

//tag::MPI_Win_flush_all[]
*MPI_Win_flush_all* completes all outstanding RMA operations initiated by the calling process to any target on the specified window.
This operation is nonlocal and all RMA operations on `win` initiated by the calling process to any target prior to this call will have completed both at the origin and at the target when *MPI_Win_flush_all* returns. *MPI_Win_flush_all* may be called only within passive target epochs.
//end::MPI_Win_flush_all[]

//tag::MPI_Win_flush_local[]
*MPI_Win_flush_local* completes all outstanding RMA operations initiated by the calling process to the target process specified by `rank` at the origin.
When this procedure returns, all RMA operations on `win` initiated by the calling process to the target will have completed at the origin but not necessarily at the target. After *MPI_Win_flush_local* returns, buffers provided to put, get, or accumulate operations may be reused.
//end::MPI_Win_flush_local[]

//tag::MPI_Win_flush_local_all[]
*MPI_Win_flush_local_all* completes at the origin all outstanding RMA operations initiated by the calling process to any target on the specified window.
When this procedure returns, all RMA operations on `win` initiated by the calling process to any target prior to this call will have completed locally.
//end::MPI_Win_flush_local_all[]

//tag::MPI_Win_sync[]
*MPI_Win_sync* synchronizes the private and public window copies of `win` at the calling MPI process.
For windows in the separate memory model, *MPI_Win_sync* synchronizes the private and public window copies. In the unified memory model, *MPI_Win_sync* may be used to order load and store accesses to shared memory and to ensure visibility of store updates for other threads and MPI processes. *MPI_Win_sync* does not complete any pending RMA operations and does not guarantee progress of any pending MPI operation. *MPI_Win_sync* is recommended to be called by both the reader and the writer of a shared memory variable between any non-RMA synchronization and access to that variable.
//end::MPI_Win_sync[]

//tag::MPI_Recv[]
*MPI_Recv* performs a blocking receive operation, storing incoming message data into the receive buffer.
The `source` argument may be `MPI_ANY_SOURCE` to accept a message from any sender, and the `tag` argument may be `MPI_ANY_TAG` to accept a message with any tag. If `source` is `MPI_PROC_NULL`, the operation returns immediately with no modifications to the receive buffer. Messages sent between a pair of processes are nonovertaking, meaning messages are received in the order they were sent.
//end::MPI_Recv[]

//tag::MPI_Buffer_detach[]
*MPI_Buffer_detach* detaches the MPI process-specific buffer currently attached to MPI.

//tag::MPI_Session_iflush_buffer[]
*MPI_Session_iflush_buffer* starts a nonblocking flush of the session-specific buffer.
This operation is nonlocal and the operation will not complete until all messages currently in the session-specific buffer of the calling MPI process have been transmitted. It is erroneous to call *MPI_Session_iflush_buffer* if there is no buffer attached to the `session`, including when automatic buffering is not enabled.

//tag::MPI_Issend[]
*MPI_Issend* starts a synchronous mode nonblocking send operation.
The call is local and returns immediately, irrespective of the status of other MPI processes. The send-complete call is nonlocal; the send can complete only if a matching receive has been started and has been matched with the send. If `dest` is `MPI_PROC_NULL`, the operation returns immediately. Nonblocking sends are ordered according to the execution order of the calls that initiate the communication, and messages sent by one MPI process to another are nonovertaking with respect to that ordering.
//end::MPI_Issend[]

//tag::MPI_Irsend[]
*MPI_Irsend* starts a ready mode nonblocking send operation.
The call is local and returns immediately, irrespective of the status of other MPI processes. A ready mode send may be started only if the matching receive is already started; otherwise, the operation is erroneous and its outcome is undefined. Nonblocking sends are ordered according to the execution order of the calls that initiate the communication, and messages sent by one MPI process to another are nonovertaking with respect to that ordering.
//end::MPI_Irsend[]

//tag::MPI_Irecv[]
*MPI_Irecv* starts a nonblocking receive operation.
The call is local and returns immediately, before a message is stored into the receive buffer. The `source` argument may be `MPI_ANY_SOURCE` to accept a message from any sender, and the `tag` argument may be `MPI_ANY_TAG` to accept a message with any tag. If `source` is `MPI_PROC_NULL`, the operation returns immediately with no modifications to the receive buffer and the status object returns `source` = `MPI_PROC_NULL`, `tag` = `MPI_ANY_TAG`, and `count` = 0. Nonblocking receives are ordered according to the execution order of the calls that initiate the communication, and messages sent by one MPI process to another are nonovertaking with respect to that ordering.
//end::MPI_Irecv[]

//tag::MPI_Isendrecv[]
*MPI_Isendrecv* initiates a nonblocking send-receive operation.
The call is local and returns immediately, irrespective of the status of other MPI processes. The `source` argument may be `MPI_ANY_SOURCE` and the `recvtag` argument may be `MPI_ANY_TAG`. Nonblocking communication operations are ordered according to the execution order of the calls that initiate the communication, and the nonovertaking message order requirement applies.
//end::MPI_Isendrecv[]

//tag::MPI_Isendrecv_replace[]
*MPI_Isendrecv_replace* initiates a nonblocking send-receive operation where the same buffer is used for both sending and receiving, so that the message sent is replaced by the message received.
The call is local and returns immediately; this operation is nonlocal as completion may depend on the occurrence of a matching receive. The semantics are what would be obtained if the caller forked two concurrent threads, one to execute the send and one to execute the receive, followed by a join of these two threads. The `source` argument may be `MPI_ANY_SOURCE` and `recvtag` may be `MPI_ANY_TAG`. A communication with `MPI_PROC_NULL` has no effect; a send to `MPI_PROC_NULL` succeeds and returns as soon as possible, and a receive from `MPI_PROC_NULL` succeeds and returns as soon as possible with no modifications to the buffer. Nonblocking communication operations are ordered according to the execution order of the calls that initiate the communication, and messages sent between a pair of processes are nonovertaking.
//end::MPI_Isendrecv_replace[]

//tag::MPI_Request_free[]
*MPI_Request_free* marks a request object for deallocation and sets `request` to `MPI_REQUEST_NULL`.
This operation is local. For an inactive `request`, *MPI_Request_free* performs the freeing stage of the associated operation during its execution. For an active `request` representing a nonblocking or persistent point-to-point operation, calling *MPI_Request_free* is permitted but strongly discouraged; in this case, *MPI_Request_free* marks the request for freeing and the actual freeing stage occurs later. Calling *MPI_Request_free* with an active `request` representing any other type of MPI operation, such as partitioned, collective, I/O, or request-based RMA operations, is erroneous. Once a request is freed, it is not possible to check for successful completion with *MPI_Wait* or *MPI_Test*, and any subsequent error is treated as fatal; active receive requests are not recommended to be freed as the receiver will have no way to verify that the receive has completed and the receive buffer can be reused.
//end::MPI_Request_free[]

//tag::MPI_Testany[]
*MPI_Testany* tests for completion of any one of a list of nonblocking communication operations.
This operation is local and returns immediately. If the `array_of_requests` contains no active handles, the call returns `flag` = true, `index` = `MPI_UNDEFINED`, and empty `status`.
//end::MPI_Testany[]

//tag::MPI_Waitall[]
*MPI_Waitall* blocks until all communication operations associated with active handles in `array_of_requests` have completed.
The `array_of_requests` may contain null or inactive handles, for which the corresponding status entry is set to empty. When one or more operations fail, the function returns MPI_ERR_IN_STATUS and the error field of each status is set to MPI_SUCCESS if the operation completed, a specific error code if it failed, or MPI_ERR_PENDING if it has neither failed nor completed.
//end::MPI_Waitall[]

//tag::MPI_Testsome[]
*MPI_Testsome* tests for completion of one or more operations associated with active handles in an array of requests.
This operation is local and returns immediately. If no operation has completed, `outcount` = 0 is returned; if there is no active handle in the list, `outcount` = `MPI_UNDEFINED` is returned. If a request for a receive repeatedly appears in a list of requests passed to *MPI_Waitsome* or *MPI_Testsome*, and a matching send has been started, then the receive will eventually succeed unless the send is satisfied by another receive.
//end::MPI_Testsome[]

//tag::MPI_Request_get_status[]
*MPI_Request_get_status* returns the status of a nonblocking operation without deallocating or inactivating the request.
The call sets `flag` = true if the operation is complete, returning the request status in `status`; otherwise it sets `flag` = false and `status` is undefined. If `request` is null or inactive, the call returns `flag` = true with empty status. A subsequent call to *MPI_Test*, *MPI_Wait*, or *MPI_Request_free* must be executed with the request to complete the operation.
//end::MPI_Request_get_status[]

//tag::MPI_Request_get_status_any[]
*MPI_Request_get_status_any* tests for completion of any one of the operations associated with active handles in an array of requests without deallocating or inactivating the request.
If one operation is complete, the call returns `flag` = true with the index and status of the completed operation; otherwise it returns `flag` = false with `index` = `MPI_UNDEFINED` and `status` undefined. If the array contains no active handles, the call returns immediately with `flag` = true, `index` = `MPI_UNDEFINED`, and empty status. A subsequent call to *MPI_Test*, *MPI_Wait*, or *MPI_Request_free* must be executed with any completed request.
//end::MPI_Request_get_status_any[]

//tag::MPI_Request_get_status_some[]
*MPI_Request_get_status_some* returns the completion status of any completed operations in an array of requests without deallocating or inactivating the requests.
If no operation is complete, `outcount` = 0 is returned; if all requests are `MPI_REQUEST_NULL` or inactive, `outcount` is set to `MPI_UNDEFINED`. If a request for a receive repeatedly appears in a list of requests passed to *MPI_Request_get_status_some*, *MPI_Waitsome*, or *MPI_Testsome*, and a matching send has been started, then the receive will eventually succeed unless the send is satisfied by another receive.
//end::MPI_Request_get_status_some[]

//tag::MPI_Iprobe[]
*MPI_Iprobe* checks for an incoming message without receiving it.
This operation is local and returns `flag` = true if a message matching `source`, `tag`, and `comm` can be received, with the `status` object set as it would be by *MPI_Recv*; otherwise it returns `flag` = false with `status` undefined. The `source` argument may be `MPI_ANY_SOURCE` and the `tag` argument may be `MPI_ANY_TAG` to probe for messages from any source or with any tag. A probe with `source` = `MPI_PROC_NULL` returns `flag` = true with `source` = `MPI_PROC_NULL`, `tag` = `MPI_ANY_TAG`, and `count` = 0. In a multithreaded environment, it is the user's responsibility to ensure that a subsequent receive using the source and tag from the probed status matches the intended message, as another thread may receive that message first.
//end::MPI_Iprobe[]

//tag::MPI_Improbe[]
*MPI_Improbe* is a nonblocking matching probe that checks for an incoming message without receiving it and returns a message handle that uniquely identifies the matched message.
This operation is local and returns immediately. The `source` argument may be `MPI_ANY_SOURCE` and the `tag` argument may be `MPI_ANY_TAG` to probe for messages from any source or with any tag. A probe with `source` = `MPI_PROC_NULL` returns `flag` = true, `message` = `MPI_MESSAGE_NO_PROC`, and a status with `source` = `MPI_PROC_NULL`, `tag` = `MPI_ANY_TAG`, and `count` = 0. In a multithreaded environment, the message handle returned by *MPI_Improbe* may be used with *MPI_Mrecv* or *MPI_Imrecv* to receive the specific message that was matched, and no other probe or receive operation may match that message.
//end::MPI_Improbe[]

//tag::MPI_Cancel[]
*MPI_Cancel* marks a pending nonblocking communication operation for cancellation.
This operation is local and returns immediately, possibly before the communication is actually cancelled. It is still necessary to call *MPI_Request_free*, *MPI_Wait*, or *MPI_Test* with the cancelled request after the call to *MPI_Cancel*. Either the cancellation succeeds or the communication succeeds, but not both. *MPI_Cancel* may be an expensive operation that is recommended to be used only exceptionally.
//end::MPI_Cancel[]

//tag::MPI_Start[]
*MPI_Start* starts a communication using a persistent request handle.
This operation is local. It is erroneous for `request` to be active when *MPI_Start* is called. Point-to-point messages are nonovertaking, meaning messages sent by one MPI process to another are received in the order they were sent.
//end::MPI_Start[]

//tag::MPI_Grequest_query_function[]
*MPI_Grequest_query_function* is a callback function type that computes the status for a generalized request.
The `query_fn` callback is invoked by *MPI_Wait*, *MPI_Test*, or their variants upon completion of the generalized request, as well as by *MPI_Request_get_status* if the request is complete. The callback is invoked only after *MPI_Grequest_complete* has been called on the request and may be invoked multiple times for the same generalized request. The `query_fn` callback is not permitted to set the error field of `status`.
//end::MPI_Grequest_query_function[]

//tag::MPI_Grequest_free_function[]
*MPI_Grequest_free_function* is a callback function type invoked to clean up user-allocated resources when a generalized request is freed.
The `free_fn` callback is invoked by *MPI_Wait*, *MPI_Test*, or their variants after the `query_fn` callback for the same request, or by *MPI_Request_free* if the request has already been completed via *MPI_Grequest_complete*. If both *MPI_Request_free* and *MPI_Grequest_complete* are called, the `free_fn` callback is invoked in whichever call occurs last. Progress toward the completion of generalized requests occurs asynchronously, such as in a separate thread or signal handler. User copies of the request handle remain valid until after `free_fn` completes, but MPI deallocates the object after `free_fn` executes and users are recommended to avoid accessing stale handles.
//end::MPI_Grequest_free_function[]

//tag::MPI_Grequest_cancel_function[]
*MPI_Grequest_cancel_function* is a callback function type invoked to start the cancellation of a generalized request.
The `cancel_fn` callback is invoked by *MPI_Cancel* and MPI passes `complete` = true if *MPI_Grequest_complete* was already called on the request, and `complete` = false otherwise. Once *MPI_Cancel* is invoked, the cancelled operation acquires local semantics and is recommended to complete in finite time irrespective of the state of other MPI processes. The `cancel_fn` callback is recommended to invoke blocking MPI communication calls only if guaranteed to return in finite time.
//end::MPI_Grequest_cancel_function[]

//tag::MPI_Grequest_complete[]
*MPI_Grequest_complete* informs MPI that the operations represented by a generalized request are complete.
Progress toward completion of generalized requests occurs asynchronously, such as in a separate thread or signal handler. Callback functions (`query_fn`, `free_fn`, `cancel_fn`) are recommended to invoke blocking MPI communication calls only if guaranteed to return in finite time. Once *MPI_Cancel* is invoked on a generalized request, the cancelled operation acquires local semantics and is recommended to complete in finite time irrespective of the state of other MPI processes.
//end::MPI_Grequest_complete[]

//tag::MPI_Comm_split[]
*MPI_Comm_split* partitions the group associated with a communicator into disjoint subgroups, creating a new communicator for each subgroup.
This operation is nonlocal and collective; each MPI process is permitted to provide different values for `color` and `key`. An MPI process supplying the `color` value `MPI_UNDEFINED` receives `MPI_COMM_NULL` in `newcomm`. The value of `color` must be nonnegative or `MPI_UNDEFINED`. Within each subgroup, MPI processes are ranked in the order defined by the value of `key`, with ties broken according to their rank in the old group. For an inter-communicator, MPI processes on the left with the same `color` as MPI processes on the right combine to create a new inter-communicator; for colors specified only on one side of the inter-communicator, `MPI_COMM_NULL` is returned. Multiple calls to *MPI_Comm_split* may be used to create multiple overlapping communication structures, and creative use of the `color` and `key` in such splitting operations is useful for defining hierarchies of computations.

*MPI_Comm_set_info* updates the hints of the communicator associated with `comm` using the hints provided in `info`.

//tag::MPI_Comm_spawn_multiple[]
*MPI_Comm_spawn_multiple* spawns multiple executables or the same executable with multiple argument sets, placing all spawned processes in a single MPI_COMM_WORLD and returning an inter-communicator.
This operation is nonlocal and may not return until *MPI_Init* has been called in the children. *MPI_Comm_spawn_multiple* is collective over `comm`, and *MPI_Comm_spawn_multiple* in the parents and *MPI_Init* in the children form a collective operation over the union of parent and child processes. `MPI_ARGVS_NULL` may be used to indicate that no arguments are passed to any commands, and `MPI_ERRCODES_IGNORE` may be passed if the caller is not interested in error codes. If unable to spawn the requested processes, an error of class MPI_ERR_SPAWN is raised. Applications that need to spawn multiple executables may use *MPI_Comm_spawn_multiple* instead of calling *MPI_Comm_spawn* multiple times, as spawning several executables at once may be faster and communication between processes spawned at the same time may be faster than communication between processes spawned separately.
//end::MPI_Comm_spawn_multiple[]

//tag::MPI_Open_port[]
*MPI_Open_port* establishes a network address at which a server can accept connections from clients.
The `port_name` is system-supplied and unique within the communication universe. A port name may be reused after it has been released by *MPI_Close_port*.
//end::MPI_Open_port[]

//tag::MPI_Close_port[]
*MPI_Close_port* releases the network address represented by `port_name`.
//end::MPI_Close_port[]

//tag::MPI_Publish_name[]
*MPI_Publish_name* publishes a (`port_name`, `service_name`) pair so that a client may retrieve the system-supplied `port_name` using a well-known `service_name`.
The behavior is undefined if `service_name` has already been published within the scope determined by `info`. The `port_name` is required to be established by *MPI_Open_port* and not yet released by *MPI_Close_port*; if it is not, the result is undefined.
//end::MPI_Publish_name[]

//tag::MPI_Unpublish_name[]
*MPI_Unpublish_name* unpublishes a service name that has been previously published.
Attempting to unpublish a `service_name` that has not been published or has already been unpublished is erroneous and raises an error of class MPI_ERR_SERVICE. All published names must be unpublished before the corresponding port is closed and before the publishing process exits. If the `info` argument was used with *MPI_Publish_name* to tell the implementation how to publish names, the implementation may require that `info` passed to *MPI_Unpublish_name* contain information to tell the implementation how to unpublish a name.
//end::MPI_Unpublish_name[]

//tag::MPI_Lookup_name[]
*MPI_Lookup_name* retrieves a `port_name` published by *MPI_Publish_name* with `service_name`.
If `service_name` has not been published, an error of class MPI_ERR_NAME is raised. If multiple entries exist with the same `service_name` within the same scope, a particular `port_name` is chosen in an implementation-defined way. If the `info` argument was used with *MPI_Publish_name* to tell the implementation how to publish names, a similar `info` argument may be required for *MPI_Lookup_name*.
//end::MPI_Lookup_name[]

//tag::MPI_Comm_join[]
*MPI_Comm_join* creates an inter-communicator from the union of two MPI processes connected by a socket.
This operation is nonlocal and does not return until both processes have called *MPI_Comm_join*. The socket must be quiescent before calling *MPI_Comm_join* and after it returns. In a multithreaded application, the application must ensure that one thread does not access the socket while another is calling *MPI_Comm_join*, or call *MPI_Comm_join* concurrently. The result of calling *MPI_Comm_join* on two already-connected MPI processes is undefined. If MPI is unable to create an inter-communicator but is able to leave the socket in its original state with no pending communication, it succeeds and sets `intercomm` to MPI_COMM_NULL.
//end::MPI_Comm_join[]

//tag::MPI_Get_processor_name[]
*MPI_Get_processor_name* returns the name of the processor on which it was called at the moment of the call.
The returned name uniquely identifies a specific piece of hardware. Users are required to provide at least `MPI_MAX_PROCESSOR_NAME` characters of storage for `name`, and may examine `resultlen` to determine the actual length of the name.
//end::MPI_Get_processor_name[]

//tag::MPI_Get_hw_resource_info[]
*MPI_Get_hw_resource_info* returns an info object containing information about the hardware platform on which the calling MPI process is executing.
This operation is local. Subsequent calls may return different information if the MPI process is relocated or has its hardware restrictions changed. The keys stored in `hw_info` may be used in *MPI_Comm_split_type* with `MPI_COMM_TYPE_HW_GUIDED` or `MPI_COMM_TYPE_RESOURCE_GUIDED` as key values for the info key `mpi_hw_resource_type`. The user is responsible for freeing `hw_info` via *MPI_Info_free*.
//end::MPI_Get_hw_resource_info[]

//tag::MPI_Free_mem[]
*MPI_Free_mem* frees memory that was previously allocated by *MPI_Alloc_mem*.
An invalid `base` argument may raise an error of class MPI_ERR_BASE.
//end::MPI_Free_mem[]

//tag::MPI_Comm_set_errhandler[]
*MPI_Comm_set_errhandler* attaches a new error handler to a communicator.
This operation is local. A newly created communicator inherits the error handler that is associated with the parent communicator; users may specify an error handler for all communicators by associating this handler with the predefined communicators before creating other communicators.
//end::MPI_Comm_set_errhandler[]

//tag::MPI_Comm_get_errhandler[]
*MPI_Comm_get_errhandler* retrieves the error handler currently associated with a communicator.
This operation is local and behaves as if a new error handler object is created. *MPI_Errhandler_free* may be called with the returned `errhandler` to mark it for deallocation when no longer needed. Library functions may register the current error handler for a communicator at entry, set a private error handler, and restore the previous error handler before exiting.
//end::MPI_Comm_get_errhandler[]

//tag::MPI_Win_create_errhandler[]
*MPI_Win_create_errhandler* creates an error handler that can be attached to window objects.
This operation is local.
//end::MPI_Win_create_errhandler[]

//tag::MPI_Win_get_errhandler[]
*MPI_Win_get_errhandler* retrieves the error handler currently associated with a window.
This operation is local and behaves as if a new error handler object is created. *MPI_Errhandler_free* may be called with the returned `errhandler` to mark it for deallocation when no longer needed.
//end::MPI_Win_get_errhandler[]

//tag::MPI_File_set_errhandler[]
*MPI_File_set_errhandler* attaches a new error handler to a file.
This operation is local. The `errhandler` must be either a predefined error handler or an error handler created by a call to *MPI_File_create_errhandler*. The default error handler for files is `MPI_ERRORS_RETURN`.
//end::MPI_File_set_errhandler[]

//tag::MPI_File_get_errhandler[]
*MPI_File_get_errhandler* retrieves the error handler currently associated with a file.
This operation is local and behaves as if a new error handler object is created. *MPI_Errhandler_free* may be called with the returned `errhandler` to mark it for deallocation when no longer needed.
//end::MPI_File_get_errhandler[]

//tag::MPI_Session_create_errhandler[]
*MPI_Session_create_errhandler* creates an error handler that can be attached to session objects.
This operation is local. Error handlers are recommended not to be called recursively with *MPI_Session_call_errhandler*, as this may create infinite recursion.
//end::MPI_Session_create_errhandler[]

//tag::MPI_Session_errhandler_function[]
*MPI_Session_errhandler_function* is a callback function type for user-defined error handling procedures invoked when errors occur on session objects.
The first argument is the session in use and the second is the error code to be returned. The remaining arguments are varargs whose number and meaning is implementation-dependent, and an implementation is recommended to clearly document these arguments.
//end::MPI_Session_errhandler_function[]

//tag::MPI_Session_set_errhandler[]
*MPI_Session_set_errhandler* attaches a new error handler to a session.
This operation is local. The `errhandler` must be either a predefined error handler or an error handler created by a call to *MPI_Session_create_errhandler*.
//end::MPI_Session_set_errhandler[]

//tag::MPI_Session_get_errhandler[]
*MPI_Session_get_errhandler* retrieves the error handler currently associated with a session.
This operation is local and behaves as if a new error handler object is created. *MPI_Errhandler_free* may be called with the returned `errhandler` to mark it for deallocation when no longer needed.
//end::MPI_Session_get_errhandler[]

//tag::MPI_Errhandler_free[]
*MPI_Errhandler_free* marks the error handler associated with `errhandler` for deallocation and sets `errhandler` to `MPI_ERRHANDLER_NULL`.
The error handler will be deallocated after all objects associated with it (communicator, window, or file) have been deallocated.
//end::MPI_Errhandler_free[]

//tag::MPI_Remove_error_class[]
*MPI_Remove_error_class* removes a user-created error class.
This function is thread-safe and may be called before MPI is initialized or after MPI is finalized. It is erroneous to call *MPI_Remove_error_class* with a value for `errorclass` that was not added by a call to *MPI_Add_error_class*, to remove an `errorclass` again without first obtaining the value from another call to *MPI_Add_error_class*, or to remove an error class when its associated error codes have not been removed before.
//end::MPI_Remove_error_class[]

//tag::MPI_Add_error_code[]
*MPI_Add_error_code* creates a new error code associated with `errorclass` and returns its value in `errorcode`.
This function is thread-safe and may be called before MPI is initialized or after MPI is finalized.
//end::MPI_Add_error_code[]

//tag::MPI_Remove_error_string[]
*MPI_Remove_error_string* removes a user-defined association of an error string with an error code or class.
This function is thread-safe and may be called before MPI is initialized or after MPI is finalized. It is erroneous to call *MPI_Remove_error_string* with a value for `errorcode` that does not have an error string added by a call to *MPI_Add_error_string*. A call adding an error string must precede a call that removes that error string, even when the procedures are called from different threads.
//end::MPI_Remove_error_string[]

//tag::MPI_Win_call_errhandler[]
*MPI_Win_call_errhandler* invokes the error handler assigned to a window with a specified error code.
Error handlers are not recommended to be called recursively with *MPI_Win_call_errhandler*, as calling *MPI_Win_call_errhandler* inside an error handler may create infinite recursion.
//end::MPI_Win_call_errhandler[]

//tag::MPI_File_call_errhandler[]
*MPI_File_call_errhandler* invokes the error handler assigned to a file with a specified error code.
Error handlers are not recommended to be called recursively with *MPI_File_call_errhandler*, as calling *MPI_File_call_errhandler* inside an error handler may create infinite recursion.
//end::MPI_File_call_errhandler[]

//tag::MPI_Session_call_errhandler[]
*MPI_Session_call_errhandler* invokes the error handler assigned to a session with a specified error code.
This function returns MPI_SUCCESS if the error handler was successfully called, assuming the process is not aborted and the error handler returns. Error handlers are not recommended to be called recursively with *MPI_Session_call_errhandler*, as calling *MPI_Session_call_errhandler* inside an error handler may create infinite recursion.
//end::MPI_Session_call_errhandler[]

//tag::MPI_Wtime[]
*MPI_Wtime* returns a floating-point number of seconds representing elapsed wall-clock time since some time in the past.
The reference point in the past is guaranteed not to change during the life of the process. Users are responsible for converting large numbers of seconds to other units if they are preferred. The `MPI_WTIME_IS_GLOBAL` attribute may be used to determine whether clocks are synchronized across MPI processes.
//end::MPI_Wtime[]
